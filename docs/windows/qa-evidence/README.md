# Windows QA evidence — 2026-09-19

These files were produced by the native WinUI application on Windows from the WSL working tree.

- `demo-main-dark.png`, `demo-main-light.png`, and `demo-settings-dark.png`: built-in memory-only account fixture, rendered by WinUI `RenderTargetBitmap`.
- `demo-tray-dark.png` and `demo-tray-light.png`: the production `TrayPopoverWindow`, using the memory-only demo adapter. The light capture exposed a foreground contrast defect that was fixed before these final captures.
- `installed-app-ui-qa.json`: live installed production v1.0.0.5 observations through official computer-use: sizing/clipping, usage refresh, token aggregation, WSL candidate dialog, hidden-window IPC and reopening. Widgets Board and screen-reader checks remain unverified.
- `demo-ipc-results.json`: 10 passing checks against a separately launched native `--demo --background` process. Covers startup without a visible management window, single-instance redirection, usage refresh, stale configuration, repeated requests, concurrent switches, completion, consistent demo device state, and settings dispatch.
- `manual-login-results.json`: six successful checks after the user completed official OAuth in a dedicated Chrome profile. Includes real usage API access, DPAPI storage and access-only export. Contains no credentials or account identifiers.
- `ssh-loopback-smoke.json`: seventeen checks using an actual local OpenSSH server with generated keys and a forced temporary home. The account credentials are synthetic; the encrypted SSH transport and POSIX helper are real.
- `wsl-computer-use-bridge.json`: the original WSL URI error reproduced against the official Windows node_repl, and fixed-marker JavaScript execution passing through the path adapter. Twelve unit tests cover path conversion, runtime discovery and preservation of permission metadata. The final prepared launcher preserved the official server name and hooks, survived desktop de-elevation, verified the override and restored the temporary user environment. `wsl-computer-use-successful-relaunch.json` records the successful live connection. This connection result alone is not Widgets Board QA.
- `core-linux-tests.txt`, `helper-contract-tests.txt`, `usage-summary-tests.txt`, `remote-codex-update-tests.txt`: local automated regression output. OS-specific Core tests report explicit skips. The helper suite deliberately terminates a synthetic `sleep` process fixture; its shell diagnostic is expected.
- `widget-extension-registration.json`: installed v1.0.0.5 OS app-extension catalog discovery and the distinct Widgets Board picker observation. Codex was registered but initially absent from the picker; restarting the existing host processes made it appear without changing the package.
- `widgets-board-ui-qa.json`: actual installed v1.0.0.5 medium widget added by the user and observed through official computer-use on Windows Widgets Board, with masked account and real usage. Button execution and large-size verification remain separate.
- `widget-medium-long-status-preview.png`: previous v1.0.0.6 design, synthetic 70-character Korean aliases and 180-character offline message, rendered from the production card at default 14px text and 8/12px small/default spacing. The renderer verifies bounds; this is not a Board DPI or live-account test.
- `Windows/CodexSyncBar.Windows/Assets/WidgetPreview.png`: the current production medium `WidgetTemplates.Render` output, with semantic quota colors and 28px remaining figures, rendered with AdaptiveCards JS 3.0.6 at 300×304 with transparent rounded corners. `widget-design-v8/results.json` records 36 passing geometry/schema checks: medium/large, nine synthetic states, light/dark themes. Includes missing five-hour data, grouped credit expirations with full weekday/date/time, expired/sub-minute credits, zero and unknown counts. PNGs in that folder are previews, not actual Board captures. `widget-design-v7/results.json` and `widget-preview-render.json` preserve the previous v1.0.0.7 and v1.0.0.6 validations. Reproduce with [WidgetPreviewExporter](../../../Scripts/Windows/WidgetPreviewExporter/README.md). This is a catalog preview, **not a screenshot of Windows Widgets Board**.

All screenshot fixture accounts and Windows/WSL/SSH devices are synthetic. IPC checks do not test real remote account changes. The screenshots verify rendered layout, not keyboard navigation, screen-reader output, or operating-system DPI changes. High contrast, Explorer restart, suspend/resume, real remote accounts/devices, and Widgets Board interaction require separate verification. Production package updates preserved the account and fresh usage; see `production-ipc-after-update.json`. Real sign-in is covered by the separate manual-login result above.

The supported computer-use tool initially failed before executing JavaScript in this WSL task with `sandboxCwd is not a local file URI: file:///home/sunggu/Projects/Personal/CodexSyncBar`. After the user restarted with the prepared launcher, the same WSL task successfully used official `@oai/sky` to list, activate and capture the installed SyncBar window. Actual captures exposed a DPI sizing issue, horizontal clipping and a token-cache EXDEV failure. The new Windows `WidgetBoard.exe` process and taskbar were not reliably targetable through the returned window list; Widgets Board QA remains incomplete. See [diagnosis and changes](../WSL-COMPUTER-USE.md). No alternate Windows UI automation was used.

Reproduce app fixture captures with `--readme-demo=popover|settings|tray --demo-theme=light|dark --readme-output=<absolute PNG path>`. Run `Windows/scripts/test-demo-ipc.ps1` with the native executable and an output JSON path to reproduce IPC checks. Both paths force the isolated demo runtime.
