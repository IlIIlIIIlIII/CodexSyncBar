# Windows 화면 설계 — v11

관리 창·트레이·위젯은 현재 적용된 계정과 API가 제공한 5시간·주간 잔여 사용량을 먼저 보여 준다. 다른 계정을 선택하는 동작과 실제로 모든 장치에 적용하는 동작을 분리한다. v11은 트레이 클릭을 관리 창 열기로 통일하고 왼쪽 계정 영역을 넓힌다. 최대 창 크기와 버튼 정렬은 유지한다. 이 문서는 구현 기준이며 빌드·실제 화면 판정은 [QA 보고서](QA.md)에 따로 기록한다.

## Windows 스타일

- 글자는 WinUI의 기본 글꼴과 `Title`·`Subtitle`·`BodyStrong`·`Body`·`Caption` 스타일을 사용해 제목, 수치, 설명의 차이를 만든다. 한글은 시스템 글꼴 대체와 텍스트 배율을 따른다. [Microsoft Typography](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography), [XAML 테마 리소스](https://learn.microsoft.com/en-us/windows/apps/develop/platform/xaml/xaml-theme-resources).
- 관리 창의 시스템 배경에는 Mica를 사용하고, 카드에는 시스템 표면·테두리 색을 사용한다. 정보 영역마다 별도 backdrop을 중첩하지 않는다. 트레이도 시스템 테마 리소스로 밝은/어두운 모드를 따른다. [Microsoft Mica](https://learn.microsoft.com/en-us/windows/apps/design/style/mica).
- 기본 간격은 8·16·24 DIP, 카드 모서리는 8 DIP를 중심으로 정리한다. 강조 색은 선택과 주요 적용 버튼에 사용하고 성공·주의·오류에는 상태 문구를 함께 둔다. 현재 SDK에 리소스가 있다는 사실과 실제 고대비·배율에서 읽기 쉽다는 판정은 구분한다.

## 화면별 정보 순서

| 화면 | 우선 보여 주는 정보와 동작 |
| --- | --- |
| 관리 창 | 왼쪽 계정 목록, 상단 별칭 편집, 현재 적용 표시와 적용 버튼, 사용량·초기화권 전용 카드, 장치 연결·최근 30일 토큰 및 비용. 제한된 창 너비에서 상세 카드는 한 열로 배치한다. |
| 트레이 | 아이콘을 클릭하면 관리 창을 표시하고 최소화 상태면 복원한다. 우클릭 메뉴는 앱 열기·사용량/장치 새로고침·종료를 제공한다. 별도 빠른 보기 팝업은 일반 진입 경로에서 제거했다. |
| 중간 위젯 | 현재 적용 계정, 제공된 한도의 큰 잔여 수치, 갱신 상태, 계정 선택, 적용·새로고침. 초기화권 상세는 큰 위젯에서 제공한다. |
| 큰 위젯 | 중간 위젯에 한도 초기화 시각, 초기화권 수량·만료 일정, 장치 적용 요약과 앱 열기를 추가한다. |

관리 창의 최대 크기는 **920×940 DIP**, 최소 크기는 **740×600 DIP**다. 실제 모니터 작업 영역이 더 작으면 제한을 함께 줄인다. 최대화 기능을 끄고 최소화·크기 조절·닫기 후 트레이 동작은 유지한다. Windows App SDK의 `OverlappedPresenter.PreferredMinimum/MaximumWidth/Height`에 DPI를 적용한 물리 픽셀 값을 전달한다. [Microsoft 창 관리](https://learn.microsoft.com/en-us/windows/apps/develop/ui/manage-app-windows).

계정 목록은 모든 지원 너비에서 왼쪽에 남는다. 창 너비 880 DIP 미만에서는 목록을 256 DIP, 그 이상에서는 336 DIP로 배치한다. 기본 너비는 v10의 224 DIP보다 50% 넓다. 상세 영역은 남은 너비를 모두 쓰고 카드는 세로로 쌓는다. 계정 적용 버튼은 카드 내용 너비 520 DIP 미만에서 다음 행으로 내려간다. 계정 관리 메뉴도 해당 동작 영역이 440 DIP 미만이면 다음 행으로 이동해 로그인 복구 버튼 공간을 확보한다. 별칭 편집·새로고침·설정은 상단 같은 행의 36×36 DIP 버튼으로 정렬해 제목 길이와 무관하게 위치를 유지한다. 두 한도가 모두 있을 때 수치 영역은 실제 너비 520 DIP 이상에서 나란히 표시한다. [Microsoft 반응형 설계 지침](https://learn.microsoft.com/en-us/windows/apps/design/layout/responsive-design)을 참고하되 크기 제한과 목록 배치는 사용자 요청을 따른다.

응답에 5시간 한도가 없으면 앱·트레이·위젯에서 해당 수치 영역을 숨긴다. 빈 수치나 0%를 만들지 않고 주간 영역이 공간을 사용하게 한다. 사용자 설정의 5시간 표시 선택은 그대로 남겨 다음 응답에서 한도가 제공되면 다시 표시할 수 있게 한다.

위젯은 한눈에 읽을 수 있는 단일 화면을 유지한다. 중간은 계정 선택과 두 버튼, 큰 크기는 앱 열기까지 제공하며 카드 내부 스크롤에 의존하지 않는다. 계정 설정과 긴 오류 상세는 앱에서 확인한다. 이는 Microsoft의 [위젯 원칙](https://learn.microsoft.com/en-us/windows/apps/design/widgets/), [크기·테마·글자 설계](https://learn.microsoft.com/en-us/windows/apps/design/widgets/widgets-design-fundamentals), [상호작용 지침](https://learn.microsoft.com/en-us/windows/apps/design/widgets/widgets-interaction-design)을 참고한 구성이다. 사용자 요청에 따른 계정 적용은 공통 제어 경로로 실행한다.

위젯의 5시간 잔여량은 녹색 계열 `Good`, 주간은 파란색 계열 `Accent`를 사용한다. 잔여량 20% 이하와 24시간 이내 만료 일정은 `Warning`으로 강조한다. 이는 호스트가 테마에 맞춰 해석하는 의미 색이며, 수치·레이블·남은 시간도 함께 표시한다. 큰 위젯은 먼저 만료되는 두 그룹의 수량과 상세 시각을 보여 주고 나머지 일정은 앱에서 확인하도록 안내한다. 중간 위젯에는 계정 선택과 적용 버튼의 공간을 확보한다.

위젯 선택기의 미리보기는 실제 중간 카드에서 300×304 PNG로 렌더하며 모서리는 투명하게 처리한다. 이 이미지는 실제 위젯 보드 실행 증거가 아니다. [Microsoft 위젯 선택기 지침](https://learn.microsoft.com/en-us/windows/apps/design/widgets/widgets-picker-integration).

## 초기화권 수량과 만료

관리 창은 초기화권을 별도 카드로 보여 주며, 수량 미확인과 실제 0개를 구분한다. 만료 정보가 없거나 일부만 제공된 경우에도 없는 날짜를 만들지 않는다. 같은 실제 만료 시각은 하나로 묶어 `2개`처럼 수량을 표시하고, 빠른 만료순으로 정렬한다.

각 그룹은 `2일 3시간 4분 남음`과 `2030.01.06 (일요일) 12:34`를 함께 표시한다. 날짜·시각은 사용자 PC의 로컬 시간이며 요일은 시스템 언어와 무관하게 한국어 전체 이름을 쓴다. 1분 미만은 `1분 미만 남음`, 만료 시각부터는 `만료됨`으로 표시한다. 관리 창과 트레이의 남은 시간은 API를 다시 호출하지 않고 저장된 만료 시각에서 매분 갱신한다. 위젯은 카드가 갱신될 때 같은 공통 포맷터로 계산하며, 앱의 분 단위 타이머가 실제 보드까지 매분 갱신한다는 뜻은 아니다.

## 한도와 과거 사용 내역

현재 제공하는 한도는 **5시간·주간 두 가지**다. Spark 한도는 화면, 설정 선택지, 사용량 응답 모델과 위젯 전달 데이터에서 제거한다. 이전 설정의 Spark 키만 정리하며 다른 사용자 설정과 지원하는 한도 값은 보존한다.

최근 30일 기록에 남은 Spark 모델의 토큰은 삭제하지 않는다. 이미 사용한 토큰의 합계와 과거 비용 추정 동작을 유지해야 하기 때문이다. 기존 가격 모델의 지원 여부도 그대로 둔다. Spark처럼 가격이 확인되지 않은 모델은 계속 미가격 항목으로 취급하며 임의 단가를 넣지 않는다.

## 새 디자인의 확인 항목

밝은/어두운 테마, 고대비, 키보드 탐색, 스크린리더 이름, 100·150·200% 배율과 서로 다른 배율의 모니터 이동을 확인한다. 740·880·920 DIP 너비에서 왼쪽 계정 목록 유지, 최대화 차단·크기 제한, 상단 별칭 편집 정렬, 주간만 있는 응답, 초기화권 0개·미확인·다중 만료를 확인한다. 긴 별칭과 오류 문구가 적용 버튼을 가리지 않아야 하며, 숨긴 5시간 영역이 접근성 탐색에 남거나 0%로 전달되지 않아야 한다. 사용량을 조회하는 상태와 계정을 적용하는 상태도 구분한다.

v8은 초기화권 포맷터 **22/22**, Linux Core **177 통과·9 제외**, Windows Core **184 통과·2 제외**, 위젯 렌더 **36/36**을 확인했다. x64·ARM64 빌드·패키징과 x64 설치를 완료했으며 실제 관리 창의 좁은 창·일반 창·최대화 재배치, 별칭 편집창, 주간 전용 표시와 초기화권 0개를 확인했다. 양수 초기화권 만료는 합성 데이터로 검사했다. 새 카드의 실제 위젯 보드와 전체 접근성·배율 검증은 남아 있으며 상세 범위는 [QA 보고서](QA.md)에 기록했다. v7 설치·화면 결과와 v5의 실제 보드 표시는 해당 이전 버전의 근거로 유지한다.


v10은 창 크기·배치만 변경한다. v8의 사용량·초기화권·위젯 검증은 해당 기능의 이전 결과로 보존하며, v10 빌드·설치와 실제 크기 조정 결과는 QA 보고서의 v10 절에 따로 기록한다.


## v11 앱 아이콘

내장 image_gen으로 만든 파란색 동기화 화살표 아이콘을 트레이·제목 표시줄·실행 파일·앱 목록·패키지/위젯 제공자 아이콘에 적용했다. [원본](../../Resources/WindowsIcon/SyncBarIcon.png)과 [최종 프롬프트](../../Resources/WindowsIcon/PROMPT.md)를 저장했다. `Scripts/Windows/prepare-icon.py`는 원본을 다시 그리지 않고 투명도를 보존하며 PNG와 16–256px의 9개 ICO 크기로 변환한다. v11의 실제 트레이 클릭·화면 검증은 WSL computer-use 연결 오류로 미실행이며 빌드·설치·아이콘 데이터 검증과 구분한다.


## v12 버튼 정렬과 위젯 구획

관리 창의 적용 버튼은 전체 폭 한 행을 사용하고, 재로그인과 계정 관리는 다음 행의 왼쪽·오른쪽에 같은 높이로 정렬한다. 창 폭에 따라 계정 관리만 아래로 이동시키던 처리를 제거했다. 로그인 취소·재시도는 별도 복구 행에 둔다.

메인과 중간·큰 위젯 모두 남은 초기화 시간과 로컬 `MM.dd (토) HH:mm` 날짜를 함께 보여 준다. 요일은 금·토 같은 한국어 한 글자다. 초기화 날짜가 없는 경우 날짜를 생성하지 않는다. 관리 창의 카운트다운은 매분 다시 계산하며 다른 계정의 지연 응답을 표시하지 않는다.

큰 위젯은 사용량과 초기화권을 각각 강조 패널로 나누고 장치 적용 상태와 계정 선택 사이에 구분선을 둔다. 앱 열기는 상단, 모두 적용·새로고침은 하단에 배치하여 세 버튼의 가로 넘침을 제거한다. Windows PC 1대는 장치 수이며 OS 버전이 아니다. 중간 위젯은 별칭과 18px 잔여량을 사용해 두 초기화 시간과 선택·적용 공간을 확보한다. 긴 오류는 요약으로 표시하고 앱에서 상세를 확인한다.

72개 합성 렌더링(9가지 상태 × 두 크기 × 두 테마 × 왼쪽/너비 채움 버튼 정렬)에서 모든 컨트롤의 가로·세로 경계를 검사했다. 실제 Windows 위젯 보드의 배율·접근성 검증과는 구분한다.
